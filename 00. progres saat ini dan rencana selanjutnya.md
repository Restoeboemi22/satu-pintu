## Rencana Selanjutnya

Urutan kerja berikut yang disarankan:

### Prioritas Setelah Finalisasi Web Admin
- fokus kerja berikutnya bukan lagi merombak halaman admin web, tetapi mulai membangun APK `GAS` dan `EduLock`,
- basis porting untuk pekerjaan APK berikutnya adalah folder `C:\Unified-System`,
- tim yang melanjutkan pekerjaan setelah fase web admin ini harus membaca poin ini sebagai arah resmi berikutnya,
- baseline web admin yang sudah dikunci pada `DATABASE`, `GAS`, `EduLock`, dan `Lentera Digital` dipakai sebagai acuan perilaku dan aturan saat melakukan porting ke APK,
- setiap pekerjaan baru setelah tahap ini harus dievaluasi apakah masuk ke jalur `porting ke APK` atau benar-benar merupakan perbaikan kritis di web admin.

### Tahap 2. Backend-first hardening
- petakan semua aksi tulis yang masih langsung dari client ke Firebase,
- kelompokkan mana yang harus dipindah ke API route atau backend function,
- prioritaskan operasi sensitif: auth, attendance, discipline, dan perubahan data master.

### Tahap 3. Stabilitas modul besar
- pecah modul `library` menjadi bagian yang lebih kecil,
- benahi error lint dan struktur hook di `virtual-pet`,
- rapikan area yang paling berisiko terhadap regression.

### Tahap 4. Penegasan arsitektur domain
- pisahkan logic store, service, dan akses data,
- buat boundary yang lebih jelas antara dashboard, admin portal, EduLock, dan modul sekolah,
- standarkan tenant scoping dan kontrak data per domain.

### Tahap 5. Validasi dan pembuktian kekokohan
- bersihkan lint bertahap,
- tambahkan pengujian untuk guard akses dan tenant scoping,
- siapkan checklist validasi sesuai prinsip dari `Kitab Suci`.
